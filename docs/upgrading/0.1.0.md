# Trill 0.1.0


## What's new

- Trill is its own project: what were Purr's online services, with its own releases, docs and repository. Purr uses it out of the box, and any engine can talk to it through its [protocol](/protocol/).
- Ownership checks: a game can play online only for players who bought it (`check_ownership`), checked at every sign-in from the copy the player uses: Steam's ticket, the App Store's AppTransaction or Google Play's Play Integrity. New games set up with `npm run setup` or `npm run configure` start with it on. See [Ownership](/ownership/).
- TURN credentials are guarded more closely: they last 4 hours for clients that renew them in the lobby (12 for those that don't), they're revoked as soon as their player leaves the lobby, and each account gets at most `TURN_DAILY_CREDENTIALS` sets a day (48 unless set). See [TURN](/turn/).
- With your own coturn servers, set `TURN_SECRET` to their shared secret and each player gets credentials of their own that end, instead of the fixed ones in `TURN_SERVERS`, which anyone who has played once can keep using.

## Changes to check

- The game setting `device_accounts` is going in the next release. To keep out players who didn't buy the game, turn on `check_ownership` with `other_stores` `false`.
- Games need a Purr release newer than 0.3.0, which speaks Trill's protocol (protocol 2). Games built with Purr 0.3.0 or earlier can't talk to Trill, and games built with a newer Purr can't talk to Purr 0.3.0's online services: update the instance and the games together.
- The protocol's headers are now `X-Trill-Game` and `X-Trill-Protocol` (they were `X-Purr-Game` and `X-Purr-Protocol`), and Steam sign-in tickets are for the identity `trill` (`GetAuthTicketForWebApi("trill")`; it was `purr-online`). A client of your own needs the same changes.
- New instances are named `trill` by default (the Worker and database `trill`, the bucket `trill-saves`). An existing instance keeps its own names: they're its settings, which updates never change.
- An instance set up from Purr's online services moves to Trill once, by hand, since its update script still looks for Purr's releases. In its folder, with your changes committed:

  ```sh
  mkdir -p /tmp/trill-release
  curl -fsSL https://github.com/NekoLabStudio/trill/releases/latest/download/trill.tar.gz | tar -xz -C /tmp/trill-release
  cp -R /tmp/trill-release/scripts /tmp/trill-release/package.json /tmp/trill-release/package-lock.json .
  mv .purr-upstream .trill-upstream
  mv .purr-version .trill-version
  npm install
  npm run update
  ```

  From then on, `npm run update` brings in Trill's releases.
- The setup command is now `curl -fsSL https://oss.nekolab.studio/trill/setup.sh | sh`, and `TRILL_VERSION` picks a release for it (it was `PURR_VERSION`).
